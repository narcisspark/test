# 초단기 호가·체결 기반 모의매매 설계안

작성 기준: 2026-11-04 KST. 이 문서는 검증할 가설과 초깃값을 정리한 설계안이다. 수익이 검증된 전략이나 실주문 기능이 아니다.

## 목적과 현재 데이터

업비트 BTC/KRW 공개 호가와 체결 흐름으로 향후 수십 초의 **비용 차감 후** 매매 손익을 추정한다. 예상 손익이 충분하지 않으면 거래하지 않는다. 현재 A~E는 1분봉 기반 비교 실험으로 계속 유지하고, 별도 F 모의 계좌에서 비교한다.

2026-11-04 16:07 KST에 확인한 기존 실행의 기록에는 호가 약 59만 건, 체결 약 12만 건이 있다. BTC 한 종목의 약 20시간 자료이므로 데이터 형식과 가설을 점검하는 초기 표본이다. 순서 오류, 끊김과 중복 여부는 실제 학습 전에 확인해야 한다.

## 데이터와 특징값

- 업비트 공개 WebSocket의 `orderbook`과 `trade`를 수신한다. 거래소 시각과 로컬 수신 시각, 종목, 원본 메시지를 보존한다. [체결 명세](https://docs.upbit.com/kr/reference/websocket-trade), [호가 명세](https://docs.upbit.com/kr/v1.6.4/reference/websocket-orderbook)
- 호가 단계별 가격과 잔량으로 최우선 매수·매도, 중간가격, 스프레드와 상위 5단계 잔량을 계산한다. 해당 단계가 충분하지 않으면 결측으로 처리한다.
- 예시 호가 불균형: `(상위 5단계 매수 잔량 합 - 매도 잔량 합) / (매수 잔량 합 + 매도 잔량 합)`. 1초와 5초 창의 값 및 변화를 사용한다. 정지된 잔량은 취소될 수 있다.
- 최근 1초·5초의 실제 체결에서 `BID`와 `ASK` 체결량의 차이를 총 체결량으로 나눠 체결 불균형을 계산한다. 체결이 없으면 0으로 꾸며내지 않고 결측/체결 없음 표시를 함께 둔다.
- 최우선 호가 잔량을 반영한 미세가격과 중간가격의 차이, 1초·5초 가격 변화, 체결 횟수, 단기 변동성 및 스프레드를 사용한다.
- 수신된 호가 스냅샷 간 변화량은 **관측된 변화의 근사치**로 기록한다. 중간에 발생한 모든 주문·취소를 복원하거나 학술적 정의의 완전한 OFI로 단정하지 않는다.

## F1: 먼저 시험할 규칙

다음은 성능이 입증되지 않은 초기 가설이다. 과거 기록에서 임의로 높은 수익이 나오는 값을 골라 고정하지 않는다.

1. 1초마다 평가하되 입력은 그 시점까지 로컬에서 수신된 메시지만 사용한다. BTC/KRW 한 종목, 가상자금 1,000만 원으로 시작한다.
2. 호가와 체결 불균형이 모두 `+0.20` 이상이고, 미세가격이 중간가격보다 높으며, 이 조건이 연속 두 번 유지되면 매수 후보로 둔다. 체결이 없는 창에서는 진입하지 않는다.
3. 최우선 호가의 나이 1초 이하, 유효한 양쪽 호가, 스프레드 0.05% 이하, 상위 매도 5단계에 목표 주문금액의 5배 이상 잔량이 있는 경우만 허용한다. 이 수치들은 초기 실험값이며 실제 피드 빈도에 따라 결측과 신호 차단 비율을 함께 본다.
4. 진입 후보가 생겨도 F2 통계 모델의 30초 예상 **순손익률**이 `+0.03%`를 넘을 때만 F2는 진입한다. F1은 모델 없이 2~3번 규칙만 적용하는 대조군이다. F1과 F2의 진입 및 결과는 독립 장부로 기록한다.
5. 청산 후보는 보유 30초 경과, 체결 불균형이 `-0.20` 아래로 연속 두 번 전환, 또는 진입 체결가 대비 관측 가능한 매도 가격이 -0.3% 이하인 경우다. 처음 충족한 조건을 기록한다. 손절 기준은 정확한 가격 체결을 보장하지 않는다.
6. 초기 가상 주문은 계좌 평가액의 5% 이내, 동시 BTC 포지션 하나, 청산 후 재진입 대기 60초다. 하루 평가손실 0.5% 이상이면 신규 진입을 중단한다. 이 값은 위험 통제를 확인하기 위한 실험값이다.
7. 연결 중단, 역전·비정상 호가, 시계 차이, 데이터 순서 오류가 감지되면 신규 진입을 중지하고 이유를 기록한다. 시세가 오래됐을 때 보유 포지션을 가상의 가격으로 임의 청산하지 않는다.

## F2: 통계 모델

- 시작 모델은 단순한 선형 회귀(Ridge)로 한다. F1 입력과 1초·5초 변화량으로 30초 뒤 청산했을 때의 순손익률을 추정한다. 기준값(평균 예측), F1 규칙과 비교하고, 더 복잡한 모델은 이후 별도로 평가한다.
- 학습의 각 입력은 의사결정 시각 `t` 이전에 수신된 데이터만 사용한다. 거래소 이벤트 시각과 수신 시각은 모두 보존하고, 수신 전 이벤트를 미리 아는 형태로 재정렬하지 않는다.
- 레이블은 `t + 가정한 주문 지연` 이후의 유효 매도 호가 단계로 매수하고, `진입 + 30초 + 청산 지연` 이후의 유효 매수 호가 단계로 매도한 가상 수익률이다. 주문 수량에 걸친 호가 단계별 VWAP와 매수·매도 수수료를 반영한다. 기록에 실제 체결/대기열 정보가 없으므로 이것은 근사치다.
- 모델 레이블이 이미 비용을 포함하므로 진입 조건에서 같은 수수료를 다시 빼지 않는다. 예측값 `+0.03%`는 불확실성을 위한 최초 여유값이며 학습으로 증명된 기준이 아니다.
- 신호 시점 호가로 체결하지 않고 지연 100ms·500ms·1,000ms를 각각 가정한다. 기준 실험에는 기존 설정의 편도 수수료 0.05%, 추가 슬리피지 0.05%를 적용하고, 실제 스프레드는 매수 ask·매도 bid에 반영한다. 호가 단계 VWAP와 추가 슬리피지가 각각 무엇을 반영하는지 별도로 표시해 중복을 피한다.
- 각 지연 시점에 신선하고 충분한 호가가 없으면 해당 주문은 미체결/평가 불가로 기록한다. F2의 30초 레이블과 조기 청산을 포함한 실제 F2 모의 결과를 따로 평가한다.

## 검증 절차

1. 원시 파일의 시각 정합성, 중복 체결 번호, 연결 공백과 누락, 스프레드·호가 단계 수를 점검한다. 가상 잔고와 P&L, 수수료의 정합성을 검증한다.
2. 초기 기록에서 시간순 학습·검증·최종 보류 구간을 나누고 구간 경계에 예측 기간과 최대 지연 이상을 비워 정보 누출을 막는다. 서로 겹치는 30초 레이블을 독립 거래처럼 취급하지 않는다.
3. 현금 보유, BTC 단순 보유, 같은 체결 가정의 무작위 진입, 기존 A~E, F1, F2를 나란히 제시한다. BTC 보유 기준선은 같은 초기자금 및 비용·평가 시각을 명시한다.
4. 체결 건수, 일별 결과, 순 기대손익/종료 거래, 승률, 손익비, 수수료·스프레드·추가 슬리피지, 최대 낙폭, 보유시간, 미체결률과 지연별 성과를 기록한다. 승률만으로 선택하지 않는다.
5. 수수료는 실제 적용 요율에 맞추고 추가 슬리피지를 2배로 한 민감도도 본다. 관측 호가 깊이와 체결 대기열이 실거래 체결을 보장하지 않으므로 결과를 낙관적/비관적 범위로 제시한다.
6. 초기 약 20시간은 개발용이다. 규칙과 학습 절차를 고정한 뒤 별도의 새로운 시세 구간에서 7일 이상 모의 운영하고, 서로 다른 시간대와 상승·하락·횡보 구간을 포함해 검토한다. 적은 거래 수와 같은 시장 구간의 상관관계를 고려해 날짜 단위 구간별 성과와 불확실성을 함께 본다.

선행 합격 기준은 순 기대손익이 비용과 지연을 반영한 미사용 구간에서도 양수이고, 일별 손실·최대 낙폭이 정한 한도 안에 있으며, 비용 증가와 지연 시나리오에서도 결과가 크게 무너지지 않는 것이다. 거래 수가 적거나 구간이 짧으면 **판정 보류**로 둔다. 이 기준을 충족해도 미래 수익이나 손실 방지를 보장하지 않는다.
